# 以 basic-memory 与 codebase-memory-mcp 作为不可修改的上游

文档域与代码域各自都有成熟的开源实现，自研的成本远高于封装。我们决定把 basic-memory（Python，文档索引）与 codebase-memory-mcp（C 二进制，代码图谱）作为黑盒上游使用，**一行代码都不修改**，本服务只做编排与网关。两者技术栈完全不同，这个约束本身就决定了本服务只能是编排器而非库级整合。

## Consequences

- basic-memory 是 **AGPL-3.0**，而我们直接 import 它的 FastAPI app。纯公司内部使用通常不构成分发，但**一旦对外部法人或客户开放，会触发 AGPL 第 13 条的源码披露义务**。这是明知并接受的风险，不是疏忽。
- codebase-memory-mcp 是 v0.10.x、实质单人维护的项目，巴士系数为 1；且只有 12 种语言有类型解析，其余退化为文本匹配，调用图会有漏边。
- 上游能力的边界就是我们的能力边界。凡是上游做不到的（例如 basic-memory 没有认证、没有真正的写冲突解决），我们要么自己在网关层补，要么不做。
