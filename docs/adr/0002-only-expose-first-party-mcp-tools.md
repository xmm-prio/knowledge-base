# 对外只暴露自研的 MCP 工具

两个上游各自都带完整的 MCP 工具集（basic-memory 约 20 个，codebase-memory-mcp 15 个）。我们决定**一个都不透传**，对外只提供自己设计的一小套面向团队场景的工具，上游工具纯粹作为内部实现调用。

理由有三：渐进式披露要求改造检索的返回体，纯转发做不到；上游的工具数量与描述长度会撑爆 agent 的上下文，而 opencode 明确把上下文膨胀列为 MCP 的首要问题；上游的接口一旦外露，将来更换上游就会破坏所有组员的用法。

## Consequences

- 唯一的例外是 `query_code_graph`，它把 codebase-memory-mcp 的 openCypher 只读查询透传出去，作为高层工具不够用时的逆向逃生口。这确实构成对上游图模式的耦合，是为了不阉割其最强能力而付出的代价，工具描述里注明了它的优先级低于高层工具。
- 上游每增加一项有价值的能力，我们要显式地为它设计一个对外语义，不会自动获得。
