# 领域文档

工程技能在探索代码库时，应按以下规则使用本仓库的领域文档。

## 探索前读取

- 根目录的 **`CONTEXT.md`**；或
- 若根目录存在 **`CONTEXT-MAP.md`**，先读取它，再读取与当前主题相关的各上下文 `CONTEXT.md`。
- **`docs/adr/`**：读取涉及当前工作区域的 ADR。多上下文仓库还应检查 `src/<context>/docs/adr/` 中的上下文 ADR。

若这些文件或目录不存在，**静默继续**：不要将其缺失视为问题，也不要主动建议创建。仅在术语或决策确实得到澄清时，由 `/domain-modeling`（可经 `/grill-with-docs` 与 `/improve-codebase-architecture` 使用）按需创建。

## 文件布局

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-<决策>.md
│   └── 0002-<决策>.md
└── src/
```

## 使用词汇表中的术语

当输出包含领域概念（例如 Issue 标题、重构建议、假设或测试名称）时，使用 `CONTEXT.md` 中定义的术语，避免改用词汇表明确避免的同义词。

若所需概念尚未出现在词汇表中，说明要么正在引入项目未使用的表达（应重新考虑），要么存在真实的术语空缺（记录给 `/domain-modeling`）。

## 标注 ADR 冲突

若输出与现有 ADR 冲突，必须明确指出，不得静默覆盖：

> _与 ADR-0007（事件溯源订单）冲突，但值得重新讨论，因为……_
