# 版本管理用 git 防抖自动提交

知识库根目录本身是 git 仓库，服务在写入后**静默一段时间才提交**，同一作者的连续写入聚合成一个 commit。

对标 Notion 的版本机制：它是全自动的时间快照（编辑中每 10 分钟一版，最后一次编辑后 2 分钟再存一版），用户从不手动提交。git 自动提交能完整覆盖这套体验，而且更强——永久保留、有 diff、可异地备份。防抖是从 Notion 那里学来的关键一环：不做防抖的话，agent 每写一条经验就是一个 commit，历史会被噪音淹没。

自建快照表被否决了，那是在重复造轮子，而且放弃了 git 生态的一切工具。

## Consequences

- 文档的时间戳不进 frontmatter，一律从 git 历史取（首次提交即创建，最近提交即更新），避免两个真相源不一致。
- 修订腐烂的经验时直接覆盖正文，不在文中保留失效的旧结论——正文永远只有当前有效的结论，变迁去翻历史。
- `codebase/` 与 `.knowledge-base/` 必须在根目录的 `.gitignore` 里，代码库有自己的 git，索引数据可重建。
